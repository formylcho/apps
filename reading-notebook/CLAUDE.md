# 読書ノート（Reading Notebook）

学術書・論文を読みながら「要約 / 気づき / 疑問」を記録し、毎日の積み重ねを
可視化する個人用の Web アプリ。現状は `index.html` 一枚で完結する静的サイト。

## いまの構成
- `index.html` のみ。ビルド不要、フレームワークなし、外部通信なし、依存ライブラリなし。
- データはブラウザの localStorage に保存（キー: `reading-notebook-v1`）。
- この `index.html` は完成済み。作り直さず、これをそのまま使う。

## 設計思想（壊さないでほしい核）
- **毎日の積み重ねが主役。** 記録のない日を責めない設計を保つ：赤い警告を出さない、
  今日まだ未記録でも連続日数をゼロにしない（「今日記録すればN+1日目」と促す）。
- **「疑問」は一級の存在。** いつか著者に送れる一問として、状態
  （未解決 → 解決 → 著者に送った）を持たせている。この扱いを維持する。
- **低エネルギーの日の逃げ道**として「今日は読んだ記録だけ残す」ボタン（読書ログ）を維持。
- 日本語 UI。見出し＝明朝／本文＝ゴシック。色の意味を保つ：
  **緑＝積み重ね（守れた日）**、**琥珀＝未解決の問い**。

## 技術・制約
- 単一の静的ファイル構成を維持する。ビルドステップ・フレームワーク・外部 CDN・
  トラッカーや解析ツールを入れない。
- バックエンドは明示の許可なく追加しない。データは当面 localStorage のまま。
- アクセシビリティを維持：キーボードフォーカス可視、`prefers-reduced-motion` 尊重、
  モバイル対応、十分なコントラスト。
- 既存のビジュアルデザインと日本語コピーを保持する。

## デプロイ（当面のゴール）
- 公開先は **GitHub Pages**（無料・HTTPS 自動）。無料枠では **public リポジトリ**が必要。
- 流れ：git 初期化 → GitHub に public リポジトリ作成 → コミット → push →
  Pages を有効化 → 公開 URL を確認して報告。
- 認証は既存の `git` / `gh`（GitHub CLI）のログインを使う。`gh` が未導入なら提案する。
- 更新は同じファイルを push し直すだけ。

## 進め方のルール（重要）
- 「公開・不可逆」の操作は**実行前に必ず確認を取る**：public リポジトリの作成、
  最初の push、GitHub Pages の有効化。
- 破壊的操作（force push、履歴書き換え、ファイル削除）も事前確認。
- 新しいアカウント作成や、トークン・パスワードの平文入力はしない。
