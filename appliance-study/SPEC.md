# 家電学習サイト 仕様書

最終更新: 2026-09-03

## 1. 目的

最新の家電について、商品ごとに体系的に学習するための個人用サイト。
購入判断のための比較サイトではなく、**商品知識を体系として身につけるための学習サイト**である。

---

## 2. 基本方針

### 2.1 「分類」と「体系」を分ける

購買フロー（形態 → グレード → メーカー）は絞り込みの順番であって、知識の構造ではない。
方式やグレードを URL 階層に固定すると、

- 新技術が出るたびに分類が破綻し、知識が分断される
- 最も学びたい「方式どうしの違い」がフォルダをまたいで消える
- 複数の軸に同時に属する商品を1本の木に押し込むことになる

したがって本サイトは 3 つのレイヤーを明確に分離する。

| レイヤー | URL | 役割 |
| --- | --- | --- |
| 住所 | `/{type}/{maker}/{series}/{model}` | 製品を引くための構造。最も安定な軸（メーカー）で固定し、不変とする |
| 体系 | `/{type}/learn/**` | 理解するための構造。区分の解説とスペック軸の解説 |
| メーカー | `/{type}/makers/{maker}` | 作り手を理解する構造 |
| 比較 | `/{type}/compare?ids=...` | 同一 type 内でメーカー横断、最大 4 件 |

形態・用途・グレードは階層ではなく **ファセット（タグ）** として持ち、絞り込みにのみ使う。

### 2.2 並列は比較表だけに集約し、本文は直列にする

学習には読む順序が必要である。カードを横に並べて俯瞰させる構成は拾い読みには向くが、
順を追った理解にはならない。よって:

- タブによる分割は行わない。1 ページ = 1 本の縦スクロール
- ポイントはグリッドではなく、上から順に読む縦積みのブロックとする（順序に意味を持たせる）
- 区分解説では区分をカードで並列に並べず、**派生の順**に連続した本文として書く
  （基本形 → その制約を解消したもの → さらに特定用途へ振ったもの）
- 見出しは 1 ページ 4〜5 個まで。増えるなら別ページに分ける
- 並列表示の役割は「比較ページ」と「各ページに 1 枚だけ置く比較表」が担う

### 2.3 段階的開示

すべてのページを次の縦のリズムで統一する。どのページでも同じ読み方ができる状態を保つ。

```
リード1文 → 一言で言うと → ポイント（縦積み） → 本文 → 出典
```

ポイントは〈質問〉→〈太字の結論 1〜2 文〉→〈グレーの根拠〉の 3 段構成とし、
太字だけ拾えば概要が掴め、根拠まで読めば理解に届くようにする。

## 3. ページ構成

### 3.1 URL

```
/                                  ホーム（商品種類の一覧とサイトの読み方）
/pc                                商品種類トップ（学ぶ／引く／比べる の3入口）
/pc/learn/                         学習マップ
/pc/learn/segments/{slug}          区分の違いの解説
/pc/learn/specs/{slug}             スペック軸の解説（CPU世代マップ等）
/pc/makers/{maker}                 メーカー解説
/pc/{maker}/{series}               シリーズ
/pc/{maker}/{series}/{model}       製品（型番）
/pc/compare?ids=a,b,c,d            比較
```

下部ナビゲーション: ホーム / 製品 / 学ぶ / 比較

### 3.2 ページ型ごとの構成

**区分解説**
```
リード1文 → 一言で言うと → 派生の順に各区分を解説（連続した本文）
→ 比較表（ここで初めて並列に俯瞰） → 選び分けの目安 → 出典
```
ポイントの質問: 何が違う？ / なぜ分かれている？ / どっちを選ぶ？

**メーカー解説**
```
リード1文 → 一言で言うと → 強み・設計思想（散文）
→ シリーズ体系の図1枚 → 型番の読み方 → シリーズ一覧 → 出典
```
ポイントの質問: このメーカーの強みは？ / ラインナップはどう並ぶ？ / 他社と何が違う？

**シリーズ**
```
リード → 一言で言うと → 何を狙った設計か → 世代の変遷（時系列1本）
→ 現行モデル一覧 → 出典
```
シリーズは学習の実質単位である。型番は年次のマイナー差分にすぎず、
「このシリーズは何を狙った設計か」がシリーズ単位で理解すべき本体。よってここを最も厚く作る。

**製品（型番）**
```
ヘッダー（メーカー・発売年月・型番・ステータス） → 一言で言うと
→ ポイント3つ → スペック表 → 詳しく読む（展開） → 出典
```
ポイントの質問: 何ができる？ / 前モデルから何が変わった？ / 誰に向く？

### 3.3 相互リンク

製品ページから「この機種が属する区分の解説へ」「このメーカーの思想へ」「このスペック項目の解説へ」
すべて辿れること。逆に体系ページからは、該当する製品がタグ経由で一覧されること。

## 4. 比較機能

- 同一 `type` 内であればメーカー横断で自由に選択、**最大 4 件**
- 選択状態は URL に保持（`?ids=`）
- 3 列目以降は横スクロール。モバイルは 2 列固定 + スワイプ
- 差分ハイライト: 全機種同値の行はグレーアウト、最良値にバッジ
- 「違いだけ表示」トグル
- スペックグループの折りたたみ
- 各行の項目名から用語解説へリンク
- 比較表に載せるのは tier1（メーカー公式）の値のみ

---

## 5. 出典ポリシー

| 層 | 対象 | 使ってよい情報 |
| --- | --- | --- |
| tier1 公式 | メーカー製品ページ・カタログ PDF | スペックの数値・機能名・型番。**比較表に載るのは tier1 のみ** |
| tier2 量販店 | ヨドバシ / ビックカメラ / ケーズ / Joshin / エディオン 等 | 区分の呼称と分け方、メーカーの一般的な特徴・傾向、売れ筋の位置づけ |
| tier3 その他 | メディア・レビュー記事 | 補足のみ。UI 上も「参考情報」として分離 |

- 全項目に `source_url` / `fetched_at` / `tier` を持たせる
- 本文中でも tier2 / tier3 由来の記述にはインラインで出典マーカーを付ける
  （学習用途では「公式情報か、量販店の言い分か」の区別自体が情報である）
- 量販店サイトは表記の誤りや古い情報が混ざるため、**数値は必ず tier1 で裏取りする**
- 各ページ末尾に「この要約は◯◯を元に作成、最終取得 YYYY-MM-DD」を固定表示
- フッターに「個人の学習用の非公式サイトです。購入判断は必ずメーカー公式をご確認ください」を常設

## 6. データ

### 6.1 配置

```
data/{type}/schema.json                       スペック項目の定義
data/{type}/makers.json                       メーカー一覧
data/{type}/segments.json                     区分（ファセット）の語彙
data/{type}/{maker}/{series}/{model}.json     製品データ
```

ファイルベースで Git 管理し、差分をレビューできる状態を保つ。

### 6.2 製品データ

```jsonc
{
  "id": "pc-fujitsu-uh90k1",
  "type": "pc",
  "maker": "fujitsu",
  "series": "lifebook-uh",
  "model": "FMVU90K1B",
  "release": "2025-05",
  "status": "current",        // current | archived
  "tags": ["mobile", "13inch", "under-1kg"],
  "lead": "…1文のリード…",
  "oneLine": "…一言で言うと…",
  "points": [{ "q": "…", "a": "…", "detail": "…" }],
  "specs": { "weight_g": 878, "…": "…" },
  "sources": [{ "url": "…", "tier": 1, "fetched_at": "2026-09-03" }]
}
```

- 単位は正規化した数値で保持する（`weight_g`, `power_w`, `capacity_l`）。表示整形は UI 側
- `schema.json` が項目定義・単位・グループ・比較時の優劣方向（`higher_is_better`）を持ち、
  比較表のヘッダー・並び順・差分ハイライトはすべてこれから自動生成する

## 7. 収集方針

- 個人の学習利用の範囲で、メーカー公式ページ・カタログ PDF からスペックと特徴を取得する
- 本文の丸ごと転載はせず、スペック値と要約として保持し、出典 URL と取得日を必ず残す
- robots.txt を尊重し、レート制限（1 req / 2s 程度）を守る
- 「クロール → 生 HTML 保存 → パーサで JSON 化 → 人手レビュー → コミット」の半自動パイプライン
- パーサはメーカーごとに 1 本ずつ書く（サイト構造が大きく異なり共通化は非現実的）
- 再取得時は差分検出し、変わった項目だけレビューする

## 8. スコープ

### 第一弾: PC（ノート・モバイル PC）

- 対象: 現行機種 + 販売終了でも発売から 6 ヶ月以内のもの
- 6 ヶ月を過ぎたものは削除せず `status: archived` として一覧から隠す（URL では到達可能）。
  世代比較の材料として旧機種の情報は必要になるため
- 価格情報は最低限（`price_note` を任意で持つのみ、比較表にはデフォルトで出さない）
- メーカー着手順: 富士通 / NEC / Dynabook / Panasonic / VAIO
  → Lenovo / HP / Dell / ASUS → Apple / Microsoft

### 進め方

1. ホームと `/pc` を作り、構造とトーンを固める ← 現在地
2. PC の `schema.json` を確定し、1 シリーズ分の実データで製品ページと比較表を作る
3. 体系ページ（区分解説・スペック解説）を実データの粒度に合わせて書く
4. クロール／パーサを自動化し、メーカーを横展開
5. 他の商品種類へ展開

## 9. 技術構成

- Next.js 15 App Router / 静的生成（`output: 'export'`）
- データはリポジトリ内 JSON、検索・絞り込み・比較はクライアント側
- DB 不要。GitHub Pages / Cloudflare Pages にデプロイ可能
- 見た目: 白カード・角丸・余白多め・ネイビー基調 + 青アクセント。
  平易な短文、専門用語には必ずその場で 1 行の言い換えを添える
